# Yuva Internship – Week 2: Logistics Data Preprocessing

## Project overview
This project demonstrates a small, reproducible workflow for collecting a logistics-related sample, checking data quality, cleaning values, and preparing a dataset for further analysis. It was prepared for the Yuva Internship Week 2 task: **Data Collection, Cleaning, and Preprocessing for Logistics Analysis**.

The public reference selected for this exercise is the [Brazilian E-Commerce Public Dataset by Olist on Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce). The dataset contains approximately 100,000 anonymised orders from 2016–2018 and related tables covering orders, order items, customers, sellers, products, payments, reviews, and geolocation. It is useful as a reference because it includes order timestamps and freight-related fields that can support delivery and logistics analysis.

**Important data note:** `sample_logistics_data.csv` is a synthetic teaching sample created for this assignment. Its 120 unique sample orders and intentionally inserted data-quality issues are not real Olist records and are not company data. The public Olist dataset was used as a reference for selecting suitable field types; the original Olist files are not included in this repository.

## What the workflow does
1. Reads the sample CSV using Pandas.
2. Standardises text fields and parses timestamp columns.
3. Converts numeric fields and marks invalid negative values as missing.
4. Removes duplicate order IDs.
5. Calculates delivery duration where valid timestamps are available.
6. Fills selected missing numeric values using the median; preserves missing reviews and unavailable delivery durations rather than inventing values.
7. Detects potential outliers using the 1.5 × IQR rule and caps selected numeric fields at the IQR fences.
8. Applies Min-Max normalisation to selected numeric features.
9. Exports a cleaned CSV and a text summary.

## Files
- `Yuva_Week2_Data_Collection_Cleaning_Preprocessing_Report.docx` – report for the internship portal.
- `sample_logistics_data.csv` – synthetic raw sample containing practice quality issues.
- `logistics_preprocessing.py` – complete Python preprocessing script.
- `cleaned_logistics_data.csv` – output generated by the script.
- `preprocessing_summary.txt` – summary of actions from the sample run.
- `requirements.txt` – required Python libraries.

## How to run
Keep the Python script and sample CSV in the same folder. Install the dependencies:

```bash
pip install -r requirements.txt
```

Run the preprocessing script:

```bash
python logistics_preprocessing.py
```

The script creates or replaces `cleaned_logistics_data.csv` and `preprocessing_summary.txt` in the same folder.

## Example run summary
- Input: 123 rows × 11 columns.
- Duplicate order rows removed: 3.
- Final cleaned data: 120 rows × 16 columns.
- Selected numeric fields are median-imputed, IQR-capped, and Min-Max normalised.
- Missing review scores and delivery durations are retained where absence has a meaningful interpretation.

These results describe only the generated sample. They are not statistics about Olist or any real logistics company.

## Limitations
The sample is intentionally small and synthetic. IQR flags potential outliers but does not prove that a value is erroneous. Any real operational analysis should inspect the original record and business context before changing unusual values. In predictive modelling, preprocessing parameters such as the scaler must be fitted on training data only and then applied to validation/test data.
